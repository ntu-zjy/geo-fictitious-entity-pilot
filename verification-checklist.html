先登记候选，再为每条待核事实保留证据。这套清单用于防止把近名机构的信息混在一起，不给商家打分，也不自动判断资质。

下载候选登记表 CSV 下载证据明细表 CSV

UTF-8（含 BOM），可用 Excel、WPS 或文本编辑器打开。模板仅预留空行和记录 ID，没有实际机构数据。导入时把信用代码、许可证号等标识列设置为文本，避免表格软件改写。

按这个顺序填写

  1. 为每个候选分配不同 ID，例如 CAND-001；先抄录 AI 原文名称和回答证据路径。
  2. 独立查询后填写官方全称、信用代码和登记状态；没有证据的字段留空，在结论列写“未确认”。
  3. 在证据明细表新增 EVID-001 等证据 ID，填写同一个候选 ID、待核表述、来源 URL、支持的原文片段、查询时间和截图位置。存在冲突也要留一行。
  4. 分别记录许可信息、合同盖章、开票和收款主体；未拿到材料不要猜填。
  5. 汇总身份结论、待解决问题和下一步动作。修改结论时写明理由和日期。

关键字段怎么理解？

字段填写要求
候选ID / 证据ID自定义且唯一，用于关联；不是官方证件号码。
官方全称 / 统一社会信用代码仅抄录核验到的官方记录；AI 输出本身不作登记依据。
登记状态原文 / 许可信息原文保留原文、日期及对应证据，不把登记状态转换成质量评级。
来源URL / 查询词 / 证据路径保留完整 URL；无法直达结果时补充入口和查询词，截图或原文另存。
核验结果建议使用“支持 / 冲突 / 不足以判断 / 查询失败”；查询失败与没有结果分开记录。
身份结论建议使用“已核对一致 / 存在冲突 / 未确认”；只描述主体身份，不写“靠谱”“保证合规”。

示例：证据不足时也能完成记录

虚构候选 CAND-DEMO 的登记全称与代码均未取得：保留空值，身份结论填“未确认”。若来源只写了相近的另一名称，在证据表写“来源不匹配”；不能填成“已核对一致”。演示不代表任何现实机构。

填写后检查三件事

  • 每条证据的候选 ID 在登记表中都有对应行。
  • 每个肯定结论都能回到具体来源和查询时间。
  • 没有把资料缺失或查询失败写成“无资质”。

填好的表留在自己的工作目录中。不要把客户合同、收款信息或个人资料上传到本实验的公开仓库。
